# LiteCoA-Search-R1 项目计划

## 0. 项目定位

项目名称：**LiteCoA-Search-R1: Multi-turn Parallel Search Agent with GRPO**

中文定位：**基于轻量链式智能体轨迹的多轮并行检索推理 Agent**

一句话概括：

> 在复现 Search-R1 的基础上，引入 CoA 的链式智能体思想，设计轻量化 `think-plan-search-information-answer` 轨迹格式；每轮 search 支持多个并行 query，同时保留多轮补搜能力。训练上先用 500 条高质量 SFT 数据做格式冷启动，再用 GRPO 优化模型何时继续搜索、何时停止回答，以及如何避免重复和无效搜索。

项目目标不是简单复现 Search-R1 或 CoA，而是做一个更适合 Qwen2.5-3B 这类小模型的 **轻量、多轮、可控、可训练的 Search Agent 框架**。

---

## 1. 背景与动机

### 1.1 Search-R1 baseline 观察

当前复现 Search-R1 后，Qwen2.5-3B 的训练指标显示：

```text
env/number_of_valid_search ≈ 1
env/number_of_valid_action ≈ 2
env/ratio_of_valid_action ≈ 1
```

这说明模型已经能稳定学会合法工具调用，但主要收敛到：

```text
search → answer
```

而不是复杂的多轮检索：

```text
search → information → search → information → answer
```

这说明 3B 模型的多轮 search 能力不稳定，但这不代表框架不应该支持多轮 search。

### 1.2 核心判断

项目设计采用以下判断：

```text
框架能力：支持多轮 search
每轮能力：支持多个 query 并行检索
SFT 目标：少量高质量轨迹做格式和行为冷启动
GRPO 目标：学习什么时候继续搜、什么时候停止
```

也就是说：

> 不能因为 3B 当前自然学不到多轮，就把系统设计成只能单轮；但也不能指望 500 条 SFT 直接教会复杂多轮策略。SFT 负责冷启动，GRPO 负责策略优化。

### 1.3 相关工作参考

- **Search-R1**：训练 LLM 在 step-by-step reasoning 中自主生成 search queries，并通过真实检索交互、retrieved token masking 和 outcome reward 做 RL 优化。论文报告 Qwen2.5-3B 相比 SOTA baseline 有 21% 提升。参考：https://arxiv.org/abs/2503.09516
- **Search-R1 GitHub**：一个用于训练 reasoning-and-searching interleaved LLM 的 RL 框架。参考：https://github.com/PeterGriffinJin/Search-R1
- **Chain-of-Agents / CoA**：通过 multi-agent distillation 和 agentic RL，让单模型模拟多 Agent 协作的问题求解流程。参考：https://arxiv.org/abs/2508.13167
- **verl Agentic RL**：verl 文档中明确支持 multi-turn conversations and tool calls、server-based asynchronous rollout 等 Agentic RL 能力。参考：https://verl.readthedocs.io/en/latest/start/agentic_rl.html
- **RAG-R1**：将检索过程从 single-query mode 扩展到 multi-query parallelism，以降低推理时间、增强搜索能力。参考：https://arxiv.org/abs/2507.02962
- **ReSearch**：面向复杂多跳问题，训练模型通过 RL 学会 reasoning with search，说明多轮检索对于复杂问题是有价值的。参考：https://arxiv.org/abs/2503.19470

## 2. 方法设计

### 2.1 总体思路

项目融合两个方向：

```text
Search-R1：提供 GRPO / RL 搜索训练框架
CoA：提供结构化 Agent 轨迹和多 Agent 蒸馏思想
```

最终方法：

```text
LiteCoA-Search-R1 = Search-R1 GRPO + 轻量 CoA 轨迹 + 每轮并行 query + 多轮补搜机制 + path-aware reward
```

### 2.2 轨迹格式设计

不直接照搬原始 CoA 的长格式：

```text
think → plan → think → search → information → think → reflection → ...
```

改成轻量版：

```text
think → plan → search → information → think → answer
```

多轮情况下：

```text
think → plan → search → information → think → search → information → think → answer
```

保留五类核心标签：

```text
<think>...</think>
<plan>...</plan>
<search>...</search>
<information>...</information>
<answer>...</answer>
```

去掉高频 `reflection`，降低 token 成本。

### 2.3 每轮并行 query

每个 `<search>` 内可以包含多个 query：

```text
<search>query1 || query2 || query3</search>
```

含义：同一轮 search action 内部并行执行多个互相独立的 query。

这样既支持单轮并行检索，也支持多轮补搜：

```text
第一轮：<search>q1 || q2</search>
第二轮：<search>q3</search>
```

### 2.4 多轮补搜机制

多轮 search 的目标不是“搜得越多越好”，而是：

> 证据不足时继续搜，证据足够时停止。

标准多轮轨迹示例：

```text
<think>这个问题需要先确认 A 和 B 的信息。</think>
<plan>
1. 查询 A 的背景。
2. 查询 B 的背景。
3. 如果证据不足，继续查询二者关系。
</plan>
<think>先并行查询 A 和 B 的基本信息。</think>
<search>A background || B background</search>
<information>...</information>

<think>目前已有 A 和 B 的基本信息，但缺少二者关系的直接证据，需要继续检索。</think>
<search>A B relationship</search>
<information>...</information>

<think>现在证据足够，可以回答。</think>
<answer>...</answer>
```

## 3. System Prompt 设计

```text
You are a search-augmented reasoning agent.

You can only use the following tags:
<think>...</think>
<plan>...</plan>
<search>...</search>
<information>...</information>
<answer>...</answer>

Rules:
1. Use <think> before <plan>, <search>, or <answer>.
2. Use <plan> to decompose the question into searchable sub-questions.
3. Use <search> to issue one or multiple search queries.
4. Multiple independent queries should be separated by "||" and searched in parallel.
5. Each <search> can contain at most 3 queries.
6. <information> is returned by the search engine and must not be generated by the model.
7. If the current information is insufficient, continue with another <think> and <search>.
8. If the evidence is sufficient, finish with <answer>...</answer>.
```

## 4. SFT 数据计划

### 4.1 数据量

第一版只做：

```text
500 条高质量 SFT 数据
```

定位：

```text
格式冷启动 + 基本 search 行为注入 + 多轮模式示范
```

这 500 条不承担完整策略学习任务，复杂的多轮 search 决策交给 GRPO。

### 4.2 数据配比

| 类型 | 条数 | 占比 | 目的 |
|---|---:|---:|---|
| 单轮单 query | 100 | 20% | 学基础搜索格式 |
| 单轮并行 query | 250 | 50% | 学 plan-guided parallel search |
| 两轮补搜 | 120 | 24% | 学证据不足时继续 search |
| 反例 / 纠错样本 | 30 | 6% | 学不要重复搜、不要乱搜 |

### 4.3 数据来源

| 数据源 | 用途 |
|---|---|
| HotpotQA / 2WikiMultiHopQA | 多跳、比较问题，适合多 query 和多轮 |
| NQ / TriviaQA | 单跳事实问答，适合单 query |
| AFM-MHQA-Agent-SFT-Dataset | 参考 CoA 轨迹风格 |
| 自建中文 QA | 用于 demo 和项目包装 |

### 4.4 数据构造流程

不要人工一条条写，采用半自动流程：

```text
公开 QA 样本
   ↓
Teacher 生成 think / plan / search
   ↓
真实 retriever 执行 query
   ↓
填充 information
   ↓
Teacher 基于 information 生成 final think / answer
   ↓
规则过滤
   ↓
人工抽查
   ↓
500 条高质量 SFT 数据
```

### 4.5 前半段生成

Teacher 生成：

```text
<think>...</think>
<plan>...</plan>
<think>...</think>
<search>q1 || q2</search>
```

要求：

```text
1. query 最多 3 个。
2. query 必须和 plan 对齐。
3. 能并行的 query 用 || 分隔。
4. 不允许编造 information。
```

### 4.6 真实检索填充 information

用真实 retriever 执行 query，填入：

```text
<information>
[Query 1] ...
Doc 1: ...
Doc 2: ...

[Query 2] ...
Doc 1: ...
Doc 2: ...
</information>
```

### 4.7 后半段生成

Teacher 基于 question、gold answer、information 生成：

```text
<think>...</think>
<answer>...</answer>
```

如果 information 不足，则生成第二轮：

```text
<think>当前证据不足，需要补充检索...</think>
<search>...</search>
```

### 4.8 数据过滤规则

| 过滤项 | 规则                                        |
| ----------- | ----------------------------------------- |
| 格式过滤 | 必须包含 think、plan、search、information、answer |
| 顺序过滤 | tag 顺序必须正确                                |
| query 数过滤 | 每轮最多 3 个 query                            |
| query 重复过滤 | 过于相似的 query 丢弃或降权                         |
| answer 过滤 | answer 与 gold answer 匹配或语义等价              |
| evidence 过滤 | information 中能找到 gold answer 或关键实体        |
| 长度过滤 | output 不超过 max length                     |
| 多轮质量过滤 | 多轮样本必须体现“第一轮证据不足，第二轮补齐证据”                 |

最终数据格式：

```json
{
  "id": "hotpotqa_xxx",
  "source": "hotpotqa",
  "question": "...",
  "gold_answer": "...",
  "queries": ["...", "..."],
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "Question: ..."},
    {"role": "assistant", "content": "..."}
  ],
  "quality_flags": {
    "format_valid": true,
    "answer_match": true,
    "evidence_hit": true,
    "num_queries": 2,
    "multi_turn": false
  }
}
```

## 5. SFT 训练计划

### 5.1 训练目标

SFT 只负责让模型学会：

```text
1. 按 tag 输出。
2. 先 think / plan，再 search。
3. 一个 search 里可以放多个 query。
4. information 是外部工具返回，模型不生成 information。
5. 证据不足时允许第多轮 search。
6. 证据足够时输出 answer。
```

### 5.2 训练配置

```text
模型：Qwen2.5-3B
训练方式：全参微调 / LoRA / QLoRA SFT 
数据量：500
max length：2048 或 4096
max search turns：2 或 3
max queries per turn：3
```

### 5.3 information Mask

`<information> ... </information>` 必须 mask 掉，不参与 loss。

原因：information 是工具返回内容，不是模型自主生成内容。模型应该学习生成 plan、query、answer，而不是学习“伪造检索结果”。

注意事项：

```text
1. 尽量在 token id 层面做 mask。
2. 不要中途 decode 再 encode。
3. 统一 information 标签前后的空格和换行。
4. 训练格式和推理格式必须一致。
```

## 6. 推理侧 Agent Loop

先实现 client / vLLM 侧 agent loop，不要一上来改 verl。

伪代码：

```python
prompt = system_prompt + user_question

for turn in range(max_turns):
    output = llm.generate(
        prompt,
        stop=["</search>", "</answer>"]
    )
    prompt += output

    if "</answer>" in output:
        break

    if "</search>" in output:
        queries = parse_queries(output)
        queries = queries[:3]
        docs = parallel_search(queries)
        prompt += format_information(docs)
```

终止条件：

```text
遇到 </search>：暂停生成，触发检索。
遇到 </answer>：结束。
超过 max_turns：失败。
```

目标：

```text
模型输出 search → 工具返回 information → 模型继续输出 answer / 第二轮 search
```

## 7. GRPO 训练计划

GRPO 阶段才是真正学习多轮策略的地方。

需要在 Search-R1 / verl 中完成：

```text
1. parser 支持 <search>q1 || q2</search>。
2. rollout 支持遇到 </search> 中断。
3. 同轮多个 query 并行检索。
4. 拼接 information 后继续 rollout。
5. information token mask。
6. 最多支持 2～3 轮 search。
7. reward 支持多轮 search 决策。
```

### 7.1 Rollout 流程

```text
Prompt
  ↓
Generate until </search> or </answer>
  ↓
If </search>: parse queries
  ↓
Parallel retrieve
  ↓
Append information
  ↓
Continue rollout
  ↓
If </answer>: finish
```

### 7.2 关键工程点

```text
1. stop_words / stop token 支持：遇到 </search> 或 </answer> 立即停。
2. batch 内同轮 query 并行检索。
3. 已完成样本需要正确处理，避免 batch shape 问题。
4. information token 不参与 policy loss。
5. 记录搜索耗时、搜索轮数、query 数、invalid rate。
```

## 8. Reward 设计

Reward 不能只惩罚搜索次数，否则模型会学成永远单轮甚至不搜。

要区分两种错误：

```text
under-search：该继续搜时没搜。
over-search：不该继续搜时乱搜。
```

推荐 reward：

```text
R_total =
  R_answer
+ R_format
+ R_query_quality
+ R_evidence_coverage
+ R_search_decision
- C_duplicate_query
- C_unnecessary_search
```

### 8.1 各项定义

| Reward | 作用 |
|---|---|
| R_answer | 最终答案是否正确 |
| R_format | tag 是否完整、顺序是否正确 |
| R_query_quality | query 是否覆盖关键实体、是否重复 |
| R_evidence_coverage | information 是否覆盖答案证据 |
| R_search_decision | 是否在证据不足时继续搜、证据足够时停止 |
| C_duplicate_query | 惩罚重复 query |
| C_unnecessary_search | 惩罚无意义补搜 |

### 8.2 多轮决策 reward

第一版可以用简单规则：

```text
如果第一轮 information 不包含 gold answer / key evidence：
    模型继续 search → 加分
    模型直接 answer → 扣分

如果第一轮 information 已包含 gold answer / key evidence：
    模型直接 answer → 加分
    模型继续 search → 小扣分
```

这比简单 `- search_count` 更合理。

## 9. 实验设计

### 9.1 对比组

| 实验组 | 说明 |
|---|---|
| Search-R1-3B baseline | 已复现的原始 GRPO |
| LiteCoA Prompt-only | 只换 prompt，不 SFT |
| LiteCoA SFT-500 | 用 500 条数据冷启动 |
| LiteCoA SFT-500 + GRPO | 主模型 |
| LiteCoA SFT-500 + GRPO + decision reward | 加多轮决策 reward 的最终版 |

### 9.2 评估指标

| 指标 | 说明 |
|---|---|
| EM / F1 | 答案准确率 |
| Format Valid Rate | tag 格式合规率 |
| Avg Search Turns | 平均搜索轮数 |
| Multi-turn Rate | 多轮 search 占比 |
| Under-search Rate | 证据不足却直接答的比例 |
| Over-search Rate | 证据足够却继续搜的比例 |
| Avg Query Count | 平均 query 数 |
| Query Redundancy | 重复 query 比例 |
| Evidence Hit Rate | 检索结果是否命中答案证据 |
| Timeout / Invalid Rate | agent loop 失败率 |
| Avg Latency | 平均延迟 |
| Avg Generated Tokens | 平均生成长度 |

### 9.3 预期结论

希望得到的结论：

```text
1. 500 条 SFT 可以显著提升格式合规率和 search 行为稳定性。
2. LiteCoA 的并行 query 能提升 evidence hit rate。
3. GRPO 能进一步提升答案准确率。
4. Decision reward 能减少 under-search 和 over-search。
5. 多轮 search 被保留下来，但不会无脑增加搜索次数。
```

## 12. 风险与应对

### 风险 1：500 条 SFT 不足以学会多轮

应对：

```text
接受这个事实。500 条只做格式冷启动，多轮策略交给 GRPO。
如果 SFT 后多轮几乎为 0，可以把两轮补搜样本从 120 条提高到 180 条。
```

### 风险 2：模型过度搜索

应对：

```text
加入 C_unnecessary_search。
统计 over-search rate。
用 evidence sufficient 规则奖励及时停止。
```

### 风险 3：模型不继续搜

应对：

```text
增加 under-search penalty。
构造更多“第一轮证据不足”的两轮样本。
在 reward 中奖励证据不足时继续 search。
```

### 风险 4：information mask 出错

应对：

```text
写单元测试。
固定 information 标签格式。
全程尽量使用 token id 操作。
避免 decode 后再 encode。
```

### 风险 5：rollout 复杂度过高

应对：

```text
先 client agent loop 跑通，再接 verl。
GRPO debug 阶段 max_search_turns=2。
每轮 max_queries=3。
```

## 15. 最终项目总结

最终项目可以概括为：

> LiteCoA-Search-R1 是一个面向小模型的多轮并行检索推理训练框架。它在 Search-R1 的 GRPO 搜索强化学习基础上，引入轻量 CoA 轨迹，让模型通过少量高质量 SFT 数据学会结构化 plan-search-answer 格式；每轮 search 支持多个并行 query，同时保留多轮补搜能力；随后通过 path-aware GRPO reward 学习何时继续搜索、何时停止回答，并控制重复搜索和无效搜索。

核心卖点：

```text
1. 支持多轮 search，不限制模型上限。
2. 每轮支持并行 query，提高检索覆盖率。
3. 500 条高质量 SFT 做低成本冷启动。
4. information mask 保证模型不学习生成工具返回。
5. GRPO 学习多轮 search 决策。
6. reward 同时控制 under-search 和 over-search。
7. 能写进简历，也能做 demo 展示。
```
